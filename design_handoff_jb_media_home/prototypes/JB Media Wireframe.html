Your own worry is right: the device frame collapses on mobile — a phone inside a phone. If you pick this, mobile drops the frame and runs the sphere full-bleed with the copy stacked above it, which is 1a in practice. That means building both anyway, so 1a is the safer single build unless you specifically want the desktop device look.
Notes before the build
Colour. The #ff8327 silk in your screenshot is a different orange from the brand gold. I would run the shader at ember/gold (#C0631C into #6B4610) so it sits under the medallion without clashing.
Load. Silk, infinite menu, drift wall, circular gallery and splash cursor are five WebGL canvases. Running all at once will drop frames on a mid-range phone, so each one pauses when scrolled out of view and mobile gets a static fallback for silk.
Photos. Everything here needs real club images — the sphere alone wants 12–20 square crops. Placeholders until you send them.
Profile cards. The React Bits card wants a transparent cut-out PNG of each person. Your current site uses rectangular photos, so those three need background removal.
Gradual blur. Applied at the hero bottom edge and above the footer only. Site-wide on every section reads as a smudge and hurts scroll performance.
